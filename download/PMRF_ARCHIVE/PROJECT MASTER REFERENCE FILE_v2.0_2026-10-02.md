## 9. Source Authority & Evidence Rules

### 9.1 سلطة المصادر (ترتيب تنازلي)
1. **شاهد مباشر مؤرخ** (Direct Observation): استجابة HTTP حية موثقة بطابع زمني — أعلى سلطة.
2. **سجل داخلي متسق** (Internal Record): worklog + سكربتات + ملفات بحث مُصدِّرة بتواريخ تنفيذ.
3. **ادعاء المصدر عن نفسه** (SOURCE_CLAIM): ما ينشره الكيان عن نفسه — يُقبل كوثيقة لسلوكه لا كتحقق مستقل.
4. **مصدر المستخدم** (USER_INPUT): خرائط وأرقام قدمها المستخدم — تُوثق كادعاء حتى يُستقل الشاهد.
5. **الاستنتاج والافتراض** — أدنى سلطة، يُوسم دائمًا (INFERENCE/ASSUMPTION/HYPOTHESIS).

### 9.2 قواعد المصالحة المطبقة
- كثرة المصادر من الجهة نفسها ≠ استقلال أدلة.
- عند التعارض: مقارنة تواريخ → سياق → سلطة → الحسم بالدليل أو وسم CONFLICTED/UNRESOLVED (§20).
- الأسعار المتغيرة عبر الزمن ليست تعارضًا بل سلسلة زمنية موثقة بطوابعها.
- **الجديد v2.0:** أدلة نظام الملفات (mtime/hash) سلطة من طبقة 2 — استُخدمت لكشف تعارض الطوابع (C9 §20) وعيوب v1.5.

### 9.3 نموذج نوع المعرفة
`FACT · SOURCE_CLAIM · DECISION · ASSUMPTION · INFERENCE · RECOMMENDATION · HYPOTHESIS · HISTORICAL · UNKNOWN · UNRESOLVED`

### 9.4 قواعد حالة التحقق (لا انتقال بدون دليل)
`UNVERIFIED → IN_REVIEW → VERIFIED` أو `IN_REVIEW → PARTIALLY_VERIFIED / CONFLICTED / UNRESOLVED`
**VERIFIED حصريًا لما فيه شاهد مباشر قابل للتتبع (ملف بحث + طابع زمني).**
