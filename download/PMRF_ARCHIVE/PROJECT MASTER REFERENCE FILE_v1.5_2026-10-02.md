## 7. Source Authority & Evidence Rules

### 7.1 سلطة المصادر (ترتيب تنازلي)
1. **شاهد مباشر مؤرخ** (Direct Observation): استجابة HTTP حية موثقة بطابع زمني (كتالوج API · قناة تيليجرام · بوابة) — أعلى سلطة.
2. **سجل داخلي متسق** (Internal Record): worklog + سكربتات + ملفات بحث مُصدِّرة بتواريخ تنفيذ.
3. **ادعاء المصدر عن نفسه** (SOURCE_CLAIM): ما ينشره الكيان عن حجمه/أسعاره (مثل «5-8k رابط/يوم» من AiVerseX) — يُقبل كوثيقة لسلوك الكيان لا كتحقق مستقل.
4. **مصدر المستخدم** (USER_INPUT): خرائط وأرقام قدمها المستخدم (مثل 142,797 مشتركًا لـgemini12pro) — تُوثق كادعاء حتى يُستقل الشاهد.

### 7.2 قواعد المصالحة المطبقة
- كثرة المصادر من الجهة نفسها (بوت + قناة + موقع لكيان واحد) ≠ استقلال أدلة.
- عند التعارض: مقارنة تواريخ → فحص سياق → تقييم سلطة → الحسم بالدليل، أووسم CONFLICTED/UNRESOLVED (القسم 17).
- الأسعار المتغيرة عبر الزمن (مثل Gemini 18M: $0.33→0.85) **ليست تعارضًا** بل سلسلة زمنية موثقة بطوابعها.

### 7.3 نموذج نوع المعرفة (مطبق في القسم 8 فصاعدًا)
`FACT · SOURCE_CLAIM · DECISION · ASSUMPTION · INFERENCE · RECOMMENDATION · HYPOTHESIS · HISTORICAL · UNKNOWN · UNRESOLVED`

### 7.4 قواعد حالة التحقق (لا انتقال بدون دليل)
`UNVERIFIED → IN_REVIEW → VERIFIED` أو `IN_REVIEW → PARTIALLY_VERIFIED / CONFLICTED / UNRESOLVED`
**VERIFIED تُستخدم حصريًا لما فيه شاهد مباشر قابل للتتبع (ملف بحث + طابع زمني).**
