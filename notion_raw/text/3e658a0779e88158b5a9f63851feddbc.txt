  Trigger model:  USER-TRIGGERED / SCHEDULED / EVENT / RESUME بحسب المتاح فعليًا. لا يُدّعى تشغيل مستمر بلا Trigger.
  Core loop:  Knowledge State → Discovery → Triage → Research → Validation → Conflict Check → Synthesis → Knowledge Commit → Quality Control → Gap Detection → Priority Queue → Next Trigger.
  Critical separation:  Knowledge State ≠ Change Type ≠ Conflict Status.
  Knowledge State:  DISCOVERED · TRIAGED · RESEARCHING · VALIDATING · SYNTHESIZED · ACTIVE · CONTESTED · CONFLICTED · INSUFFICIENT_EVIDENCE · DUPLICATE · OUTDATED · SUPERSEDED · REJECTED
  Change Type:  CREATED · CONFIRMED · UPDATED · CORRECTED · CONTEXTUALIZED · DUPLICATED · SUPERSEDED · REJECTED
  Conflict Status:  NONE · OPEN · RESOLVED · PARTIALLY_RESOLVED

  6.3 معايرة RSH-17

  No Verified Execution = No Claim of Execution
  No Evidence = No Knowledge Commit
  No Verified Persistence = No Final State Change
  Scheduled ≠ Continuous Process
  Research ≠ Knowledge Asset
  Search Result ≠ Knowledge Commit
  Commit Success ≠ Commit Verification
  SUPERSEDED ≠ DELETED
  Knowledge State ≠ Change Type ≠ Conflict Status ≠ Commit Status

  27. Continuity Hardening — الاستمرارية غير المنقطعة على مستوى المنظومة
  مقصود «لا تتوقف المنظومة» هو  عدم وجود نهاية تشغيلية مخططة للمنظومة ككل ؛ وليس إبقاء نموذج واحد في تنفيذ حي بلا انقطاع. كل Run ينتهي كدورة منفصلة، لكن الحالة المحفوظة والعمل التالي يبقيان قابلين للاستئناف بواسطة Trigger لاحق فعلي.
  قاعدة الاستمرارية:
  PERSIST VERIFIED STATE → DETERMINE NEXT WORK → PRESERVE OPEN WORK / GAPS → NEXT TRIGGER → READ STATE → RESUME
  ولا توجد حالة طبيعية اسمها “انتهاء المنظومة”. الحالات النهائية تخص  الدورة أو الوحدة أو التغيير  فقط، وليست دورة حياة المنظومة ككل.
  28. Run Admission & Overlap Protection
  قبل أي معالجة:
  READ CURRENT PERSISTENT STATE → CHECK ACTIVE TRIGGER → CHECK RECENT CYCLE STATE → DETECT POSSIBLE OVERLAP / DUPLICATION → ADMIT ONE VALID WORK UNIT
  لا تبدأ دورة جديدة على نفس  Research_ID / Knowledge_ID / Change_ID  إذا كانت هناك محاولة حديثة غير محسومة؛ يجب أولًا:
  RECONCILE → VERIFY → RESUME / RETRY
  الهدف منع السباق بين الدورات والتكرار المزدوج والتعديلات المتعارضة.
  29. No-Work / No-Change Continuity
  عندما لا يوجد عمل معرفي يستوفي شروط التنفيذ:
  NO_CHANGE → PERSIST STATE → DETERMINE NEXT VALID WORK → NEXT TRIGGER
  لا تُنشأ أبحاث أو Knowledge Assets مصطنعة للحفاظ على مظهر النشاط. الاستمرارية المعرفية لا تعني إنتاج ضوضاء.
  30. Recovery-First Execution
  أي فشل في أداة أو كتابة أو تحقق لا يبرر بدء مسار جديد قبل استعادة الحقيقة التشغيلية:
  FAILURE → PRESERVE LAST VERIFIED STATE → RECONCILE → RESUME / RETRY → VERIFY
  إذا تعذر الإصلاح الموثوق:
  BLOCKED
  مع بقاء آخر حالة موثقة وعدم الادعاء بحدوث التغيير.
  31. Research Anti-Stagnation
  إذا كررت الوحدة البحثية نفسها دون اكتساب Evidence جديد أو تغيير في المعرفة:
  DO NOT REPEAT IDENTICALLY
  بل:
  RETRIAGE → IDENTIFY WHY PRIOR ATTEMPT FAILED / SATURATED → CHANGE RESEARCH STRATEGY OR SOURCE SET → RESEARCH
  يمنع ذلك الدوران اللانهائي حول السؤال نفسه مع نفس الأدلة.
  32. Knowledge Delta Gate
  لا يُعتمد Commit معرفي لمجرد وجود مادة جديدة. يجب إثبات أحد الآتي:
  CREATED / CONFIRMED / UPDATED / CORRECTED / CONTEXTUALIZED / DUPLICATED / SUPERSEDED / REJECTED
  وإذا لم يوجد فرق معرفي جوهري:
  NO_CHANGE
  33. Continuity Invariant
  يجب أن تنتهي كل دورة موثوقة بأحد مسارين:
  A. VERIFIED KNOWLEDGE COMMIT → UPDATED STATE → NEXT WORK
  أو
  B. NO_CHANGE / PARTIAL / BLOCKED → PERSIST LAST VERIFIED STATE + OPEN WORK + NEXT WORK
  لا يجوز أن تنتهي الدورة دون تحديد ما سيُفعل لاحقًا أو لماذا تعذر تحديده.
  34. Canonical Trigger Invariant
  للوظيفة نفسها:
  ONE ACTIVE CANONICAL TRIGGER
  وعند كل فحص:
  DETECT → VERIFY ACTUAL STATUS → REMOVE / DISABLE DUPLICATE → REVERIFY
  لا تكفي تسمية المهمة، ولا يُقبل اعتماد حالة غير مؤكدة.

Historical use of licensing in some tier schemes is not evidence that licensing alone defines ERP.
