# Central Automation Runtime — سجل التنفيذ والبنية الحالية — 2026-09-26
قرار البنية
الهدف:  Runtime مركزي واحد للأتمتة يخدم جميع المشاريع.
قاعدة معمارية:  لا يتم إنشاء Runtime مستقل لكل مشروع. المشاريع تُعامل كـ Projects/Jobs داخل محرك مركزي واحد.
البنية المستهدفة
Central Runtime
├── Trigger / Scheduler
├── Orchestrator
├── Project Registry
├── Global Work Queue
├── Worker Execution
├── Validation
├── Idempotency
├── Retry Budget + Backoff
├── Lease / Ownership
├── Reconciliation
├── Dead-Letter / Quarantine
├── Observability
├── Watchdog / Recovery
└── Persistent State

قيود التنفيذ الحالية
1. Production Runtime
Render رفض إنشاء Postgres مدفوع بسبب عدم وجود وسيلة دفع في الحساب.
الحالة:  BLOCKED — Billing prerequisite.
2. Repository Isolation
GitHub integration الحالية منعت إنشاء Branch مستقل للـRuntime.
الحالة:  BLOCKED — Repository permission.
لا يجوز تعديل مشروع قائم أو خلط Runtime المركزي مع كود مشروع أعمال دون قرار معماري مقصود.
3. Durable Runtime
لا يجوز اعتبار Runtime مكتملًا حتى يتوفر:
- Compute دائم.
- Persistent State.
- Queue durable.
- Ownership/Lease.
- Recovery.
- Verification.
- Observability.
الفرق بين Prototype وProduction
Prototype يمكن أن يثبت:
- API.
- Queue model.
- Scheduling logic.
- Retry logic.
- Health endpoints.
- Job lifecycle.
لكنه لا يساوي 24/7 Production إذا كان التخزين مؤقتًا أو الخدمة Free.
Render يوضح أن Free Web Services تتوقف بعد 15 دقيقة من عدم وجود حركة واردة، وأنها ليست مخصصة للإنتاج؛ كما أن Free Postgres مؤقت وينتهي بعد 30 يومًا. لذلك لا يُسمّى هذا الوضع Production 24/7.
