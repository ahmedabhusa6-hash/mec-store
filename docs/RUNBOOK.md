# MEC — دليل التشغيل (Runbook)

## التشغيل اليومي (آلي بالكامل)
- المراقب يعمل كل 30 دقيقة عبر GitHub Actions (لا تدخل مطلوب)
- اللوحة تعرض حالة كل دورة (قسم الأتمتة) والتنبيهات الحرجة تلقائيًا

## إجراءات المالك من اللوحة (/dash)

| الإجراء | القسم | ما يحدث |
|---------|-------|---------|
| اعتماد انضمام خاص | الاكتشافات والموافقات | الحالة → approved + إطلاق دورة فورية تلقائيًا تنفّذ الانضمام |
| رفض انضمام خاص | الاكتشافات والموافقات | الحالة → rejected نهائيًا |
| إضافة مرشحين (مقابض/روابط) | الاكتشافات والموافقات | إدراج يدوي → تقييم المراقب في أقرب دورة |
| تشغيل دورة الآن | الشريط العلوي / الأتمتة | workflow_dispatch فوري (يحترم قفل التزامن) |
| ضبط سياسات الانضمام | الإعدادات والحوكمة | قيم تنسحب من بداية الدورة التالية |
| رفع قواطع الأمان | الإعدادات والحوكمة | استئناف فوري (استخدم بحذر — راجع سبب القاطع أولًا) |

## الاستجابة للتنبيهات

| التنبيه | المعنى | الاستجابة |
|---------|--------|-----------|
| قاطع أمان (حرج) | PeerFlood/FloodWait على الانضمام | انتظر انتهاء المدة (تلقائي) أو ارفع بعد فهم السبب |
| فشل/تعطل دورة (حرج) | خطأ غير معالج في المراقب | راجع سجل GitHub Actions للدورة المعنية |
| أخطاء غير حرجة (تحذير) | أخطاء قنوات فردية | لا تدخل عادة — إعادة المحاولة تلقائية |
| محاولة دخول فاشلة (أمن) | بيانات دخول خاطئة | تجاهل إن كانت منك؛ راجع IP إن تكررت |

## استرداد الدخول
كلمة مرور المالك = متغير البيئة OWNER_PASSWORD (Railway). تغييره في Railway ثم تسجيل الدخول به يُحدّث التجزئة المخزنة تلقائيًا.

## الطوارئ
- **إيقاف كل الانضمام**: الإعدادات → ضبط join_budget = 0 (يسري من الدورة القادمة)
- **إيقاف المراقب مؤقتًا**: GitHub → Actions → Price Monitor → disable workflow
- **رجوع إصدار الويب**: Railway → Deployments → rollback للنشر السابق

## مزامنة مزودي API (v2.1)
- يقرأ المراقب سجل `providers` في بداية كل دورة (معزول تمامًا عن مسار تلغرام).
- لتفعيل Reloadly: أنشئ حسابًا (reloadly.com) → انسخ client_id/client_secret من
  لوحة Reloadly (وضع LIVE أو TEST) → أضفهما كأسرار GitHub Actions
  (RELOADLY_CLIENT_ID / RELOADLY_CLIENT_SECRET) → من لوحة التحكم: التكاملات →
  اضغط «علّمت الاعتمادات كمتوفرة». الدورة القادمة ستختبر الاتصال وتسجل الحالة الفعلية.
- أي فشل مزود لا يوقف بقية الدورة؛ حالته تُحدَّث (AUTH_FAILED / RATE_LIMITED) مع السبب.
- طلبات الشراء (orders) غير مفعلة إطلاقًا في المنصة — تتطلب موافقة المالك المسبقة.
