# MEC — معمارية المنصة (v4، إعادة البناء 2026-10-11/12)

## المخطط العام

```
تلغرام (قنوات/مجموعات الموردين)
        │  مسح تفاضلي كل 30 دقيقة + عند الطلب
        ▼
GitHub Actions ── price-monitor/monitor.py (v3)
        │  Telethon (جلسة المالك) + انضباط شروط الخدمة
        ▼
Supabase (mec-store) ── جداول الحقائق + settings + alerts + audit_log
        │  PostgREST (مفتاح خدمي يتجاوز RLS)
        ▼
تطبيق الويب (Next.js 16 على Railway)
   ├── /            قاعدة الأسعار العامة (facts-only + انتعاش)
   ├── /login       مصادقة المالك (scrypt + جلسة موقعة HMAC)
   └── /dash        لوحة التحكم (11 قسمًا) + /api/admin/*
```

## المكونات

| المكوّن | الموقع | الدور |
|---------|--------|-------|
| المراقب v3 | `price-monitor/monitor.py` | مسح تفاضلي دوّار، استخراج أسعار/إشارات، اكتشاف مقابض وروابط دعوة، انضمام منضبط (عام تلقائي / خاص بموافقة المالك)، تنبيهات وتدقيق |
| الجدولة | `.github/workflows/price-monitor.yml` | cron */30 + workflow_dispatch (بمدخل dispatched_by من اللوحة) |
| قاعدة البيانات | Supabase `mec-store` | جداول: tg_channels, price_observations, statements, discoveries, runs, settings, app_users, alerts, audit_log + views تجميعية (v_*) + RLS deny-by-default |
| تطبيق الويب | `src/` (Next.js 16, TypeScript, Tailwind, shadcn/ui) | طبقة بيانات Supabase حية (REST + كاش 60ث)، مصادقة مالك، واجهة عامة + لوحة تحكم |
| CI | `.github/workflows/ci.yml` | lint + tsc للويب، py_compile للمراقب |

## دورة البيانات → القرار

1. **جمع**: المراقب يقرأ الرسائل الجديدة فقط (مؤشر last_msg_id لكل مصدر، دوّار الأقدم مسحًا أولًا)
2. **استخراج**: بنك regex مُجرَّب (C3) → أسعار/ضمانات/شروط بدليل خام (raw_text يبقى خاصًا)
3. **اكتشاف**: مقابض @ وروابط دعوة t.me/+ من النصوص والروابط والأزرار
4. **قرار الانضمام**:
   - عام تجاري → انضمام تلقائي (≤3/دورة، فاصل 12-30ث)
   - خاص → معاينة قراءة-only → `awaiting_approval` → المالك يعتمد/يرفض من اللوحة → `approved` → دورة فورية تنفّذ
5. **عرض**: الموقع العام (facts + حالة الانتعاش) واللوحة (KPIs، جودة، أتمتة، تنبيهات، تدقيق، إعدادات)
6. **قياس**: runs يسجل كل دورة (قنوات/رسائل/أسعار/انضمامات/أخطاء) + مؤشرات الجودة محسوبة من v_freshness

## الأمان

- كلمات المرور: scrypt (salted) — لا نص صريح أبدًا
- الجلسة: كوكي httpOnly موقّع HMAC-SHA256 (14 يومًا) + bootstrap من متغيرات بيئة المالك
- كل مسارات /api/admin/* تتحقق من الجلسة؛ دخول فاشل → تنبيه أمني + سجل تدقيق
- حدود معدل: دخول 8/دقيقة، إرسال دورة 4/دقيقة (لكل IP + سقف عامي)
- Supabase: RLS مفعّل بلا سياسات عامة (مفتاح الخدمة فقط) — القراءة العامة عبر تطبيق الويب حصريًا
- الأسرار: متغيرات بيئة على Railway/GitHub فقط، لا أسرار في المستودع إطلاقًا

## حدود معروفة

- تحديث الأسعار مقيد بمعدل مسح آمن (فريم FloodWait) — p95 ≈ 35 دقيقة عند ~84 مصدرًا
- سقف المصادر 250 (حد تلغرام 500 بهامش مضاعف) — الرفع إلى ~400 قرار مالك من الإعدادات
- القنوات التي تشترط موافقة مشرف تُتخطى (لا تُرسل طلبات — سياسة مكافحة السبام)
- مزامنة الموردين عبر API الرسمية غير متاحة (لا مورد يقدمها — مثبت 2026-10-09)
